## Next.js version notes

Installed: next 16.4.6 (docs read from `node_modules/next/dist/docs/01-app`). Scaffold sets `cacheComponents: true` and `partialPrefetching: true` in `next.config.ts`.

- `params` and `searchParams` are Promises in pages, layouts and route handlers: `async function Page({ searchParams }: { searchParams: Promise<{...}> }) { const q = (await searchParams).q }`; route handlers use `{ params }: { params: Promise<{ id: string }> }` then `await params`. Globally available typed helpers `PageProps<'/route'>`, `LayoutProps`, `RouteContext` are generated by `next dev`/`next build`/`next typegen`. Reading `searchParams` opts the page into dynamic (request-time) rendering.
- With `cacheComponents: true`, the route segment configs `dynamic`, `revalidate`, `fetchCache` (and `dynamicParams`) are REMOVED; do not export them. Data fetching is dynamic by default; opt into caching with the `'use cache'` directive (+ `cacheLife`, `cacheTag` from `next/cache`).
- Under Cache Components, any uncached/runtime data access (DB queries, `searchParams`, `cookies()`, `headers()`, `connection()`) in a page must sit under a `<Suspense>` boundary or the build reports a blocking-route error. Plan: put data-reading components in their own async component wrapped in `<Suspense fallback=...>`.
- The `runtime` route segment config is not supported with Cache Components (Node.js runtime only); do not export `runtime`.
- Route Handlers: not cached by default; `export const dynamic = 'force-static'` is the old model and is unavailable with Cache Components (GET handlers prerender unless they touch request/uncached data, which is our case). Reading `request.url`/headers or DB queries makes them request-time.
- Server Actions/Functions: use the `'use server'` directive (top of an async function or file); invoked from `<form action={fn}>` or `startTransition`. Body size limit and `allowedOrigins` are configured under `serverActions` in `next.config.ts` (`bodySizeLimit` default 1MB; raise it for file uploads).
- Middleware is now called `proxy` (`01-getting-started/16-proxy.md`); not needed for this project.
- Tooling: @types/node was bumped to ^22 because vitest 5 peers require `^22 || >=24`; Next itself is unaffected.
